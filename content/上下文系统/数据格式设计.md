# 📐 数据格式设计

## 核心设计原则

1. **无损失** — 原始结构化数据完整保存在 `metadata` 中
2. **可理解** — `content` 用自然语言让 Hindsight 的 LLM 正确提取事实
3. **可追踪** — 每条记忆带原始 `document_id`，支持去重
4. **可扩展** — 未来增加新数据源不需要改 schema

## MemoryItem 结构

```yaml
# Hindsight API POST /memories 的请求体
{
  "content": "用户使用 {app} 在 {time} 做了 {action}，涉及文件/内容：{summary}",
  "metadata": {
    "source": "screenpipe | openchronicle",
    "document_id": "原始数据源中的唯一 ID",
    "timestamp": "2026-05-10T12:34:56+08:00",
    "app_name": "VS Code",
    "event_type": "file_edit | app_switch | url_visit | screen_ocr",
    # 数据源特有字段...
  },
  "tags": ["operation_memory", "{data_source}", "{app_name_lowercase}"],
}
```

### Screenpipe 示例

```json
{
  "content": "用户在 Firefox 中浏览了关于 LLM prompting 的长篇文章，页面提到了 chain-of-thought 和 few-shot learning 技术",
  "metadata": {
    "source": "screenpipe",
    "document_id": "frame_20260510_123456_001",
    "timestamp": "2026-05-10T12:34:56+08:00",
    "app_name": "Firefox",
    "event_type": "screen_ocr",
    "ocr_text": "(完整 OCR 文本)",
    "window_title": "Prompt Engineering Guide — 知乎"
  },
  "tags": ["operation_memory", "screenpipe", "firefox"]
}
```

### OpenChronicle 示例

```json
{
  "content": "用户在 VS Code 中打开了 Hermes 项目的 config.yaml 配置文件，编辑了 deepseek provider 的 api_key 配置项",
  "metadata": {
    "source": "openchronicle",
    "document_id": "event_20260510_123400_abc",
    "timestamp": "2026-05-10T12:34:00+08:00",
    "app_name": "Code",
    "event_type": "file_edit",
    "file_path": "/Users/igloo/.hermes/config.yaml",
    "project": "hermes-agent"
  },
  "tags": ["operation_memory", "openchronicle", "code"]
}
```

## 去重逻辑

每次推送前，记录已推送的 `document_id` 集合（持久化到本地文件 `~/.hermes/longterm_memory/pushed_ids.json`），新推送时跳过已存在的 ID。

## 增量读取

维护 `last_push_timestamp`，每次只读取该时间戳之后的新记录。时间戳保存于 `~/.hermes/longterm_memory/state.json`。
