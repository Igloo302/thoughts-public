# 总定义

这个系统的本质不是“长期记忆”，而是一个跨设备个人上下文系统：

> 一个跨设备个人上下文系统，以 AI 眼镜、PC、手机和 Agent 对话捕捉用户经历，以公共知识源感知世界变化，以共享经验网络连接他人的经验，并通过三条主线完成转化：把经历转化为记忆和洞察，把世界知识转化为个性化任务上下文，把经验转化为共享知识或可执行技能。最终，Agent 在对话、任务、提醒、复盘、创作和行动中调用这些上下文资产，同时由隐私、权限、来源、时效、确认和可解释机制贯穿治理。

更简洁地说：

> 把一个人在现实世界、数字世界和知识世界中的经历，持续转化为可理解、可控制、可复用、可分享、可执行的上下文资产。

这个系统不是简单“记住更多东西”，而是解决四件事：

1. **理解我经历了什么**

包括现实世界、数字世界、社交关系、任务过程。

2. **理解我关心什么**

包括兴趣、项目、长期目标、偏好、判断标准。

3. **理解世界中什么和我有关**

不是全量吸收世界知识，而是筛选、订阅、更新与我相关的知识。

4. **把经验转化为可用资产**

有些变成记忆，有些变成洞察，有些变成共享经验，有些变成可重复执行的 Skill。

它的原则
```plaintext
不是所有信息都要存。
不是所有知识都要进入我的库。
不是所有经验都只应该被总结，有些应该变成行动能力。
```


# 输入通道

系统的信息来源可以分成六类。

```plaintext
1. AI 眼镜
现实世界上下文：
我看到了什么、听到了什么、在哪里、见了谁、参与了什么现实事件。

2. PC 端
数字工作上下文：
网页、文档、代码、会议材料、搜索、软件操作、任务流、项目资料。

3. 手机端
随身生活上下文：
日程、位置、聊天、联系人、照片、提醒、消费、地图、临时想法。

4. Agent 对话
协作上下文：
我和 Agent 讨论过什么、确认过什么、否认过什么、共同形成了哪些概念。

5. 公共世界知识
公开信息：
新闻、论文、产品资料、官方文档、网页、数据库、行业报告。

6. 共享经验网络
他人或他人 Agent 授权分享的经验：
不一定公开可搜索，但对我有意义，比如朋友的踩坑、某个用户的真实体验、一个小圈子里的经验资产。
```


这里最关键的修正是：**共享经验知识不是“社区内容”的同义词**。它的本质是：

> 来自某个主体的真实经验，经过提炼和授权，可以被别人使用。

# 三条转化主线

原始数据不会直接进入长期记忆。系统要先做理解、筛选和结构化。

主要加工动作包括：

```plaintext
Capture
捕捉多源信息。

Understand
理解音频、视频、文本、行为，把它们转成事件、实体、关系、任务。

Extract
提取值得记住的事实、偏好、承诺、判断、经验。

Reflect
从多条记忆中总结模式、偏好、信念、洞察。

Organize
按人、地点、时间、主题、任务、兴趣、项目组织。

Retrieve
在对话和任务中召回相关上下文。

Update
更新过期信息，修正错误信息，合并重复信息。

Forget
删除、降权、归档、过期处理。

Share
把个人经验脱敏、整理、授权后变成共享经验。

Compile
把可重复经验转化为 Skill。
```


**三条转化链路共同汇入一个 Personal Context System**。

```plaintext
1. 经历线：Experience → Memory → Insight
我经历了什么 → 我记住什么 → 我理解了什么


2. 知识线：World Knowledge → Interest Knowledge → Context
世界发生什么 → 什么和我有关 → 如何影响我的任务


3. 经验线：Experience / Practice → Shared Experience / Skill
什么做法有效 → 能否分享给别人 → 能否变成技能
```


也就是说，系统处理的不是一种信息，而是三类不同价值的转化。

## 主线一：经历到记忆，再到洞察

这条线处理的是：**我亲自经历了什么，以及这些经历说明了什么。**

来源包括：

- AI 眼镜看到、听到、感知到的现实经历
- PC 上的工作行为
- 手机上的生活、社交、日程、位置
- 我和 Agent 的对话与协作历史
  
转化过程是：

```plaintext
Raw Experience
原始经历

↓ 事件化、结构化、筛选

Private Memory
私人记忆

↓ 反思、归纳、模式识别

Personal Insight
个人洞察
```


例子：

```plaintext
你多次讨论 AI 眼镜、长期记忆、隐私、共享经验。

↓ 记忆

你正在构建一个跨设备个人上下文系统的理论框架。

↓ 洞察

你真正关心的不是“记录更多”，而是如何把现实经历、知识和经验转化为可控、可复用、可分享的上下文资产。
```


这条线的核心价值是：

> 让 Agent 更理解“我是谁、我经历了什么、我为什么这样想”。

它产出的主要资产是：

- Private Memory
- Task Context
- Preference Memory
- Relationship Memory
- Personal Insight
  
## 主线二：世界知识到个性化知识，再到任务上下文

这条线处理的是：**世界上发生了什么，以及哪些事情和我有关。**

来源包括：

- 新闻
- 论文
- 产品资料
- 官方文档
- 行业报告
- 网页
- 数据库
- 公开社区内容
  
但这条线的重点是：**不全量采集世界知识。**
```plaintext
不存全量世界
只维护与用户相关的索引、摘要、来源、订阅、变化和影响判断
```


它不是：

```plaintext
把所有信息存进我的系统
```


而是：

```plaintext
根据我的兴趣、任务、项目和历史上下文，筛选世界知识
```


转化过程是：

```plaintext
Public World Knowledge
公共世界知识

↓ 相关性筛选、来源校验、摘要、订阅

Personalized / Interest Knowledge
个性化兴趣知识

↓ 和当前任务、对话、决策结合

Task / Decision Context
任务与决策上下文
```


例子：

```plaintext
世界上发布了一款新的 AI 眼镜。

↓ 个性化筛选

它和你关注的全天佩戴、现实感知、隐私边界、Agent memory 有关。

↓ 进入上下文

下次你讨论产品架构或竞品研究时，Agent 会把它作为相关背景带入。
```


这条线的核心价值是：

> 让 Agent 不只记得你，还知道世界中哪些变化对你重要。

它产出的主要资产是：

```plaintext
Knowledge Reference
曾经被使用或引用过的知识，保留摘要和来源。

Interest Knowledge
用户长期关注的领域，持续监测变化。

Distilled Knowledge
被系统消化后的趋势、结论和判断。

Cached Evidence
临时缓存的证据，用于追溯，可以过期和刷新。

……

Watchlist
Knowledge Updates
Decision Context
```


这条线必须有生命周期：

```plaintext
发现 → 判断相关性 → 摘要/引用 → 使用 → 更新 → 过期/归档
```

> 相关性、来源、时效、更新、冲突处理。

## 主线三：经验到共享经验，或到技能

来源包括：

```plaintext
1. 用户重复行为
系统发现用户经常按某种方式完成任务。

2. 用户明确指令
用户说“以后都按这个流程”。

3. Agent 反思建议
系统发现某件事可以沉淀成流程，但需要用户确认。

4. 他人共享经验
别人或别人的 Agent 分享了一个有效 Skill。

5. 公共知识编译
从官方文档、最佳实践、教程中生成可执行步骤。
```


这条线处理的是：**哪些经历和做法可以被复用。**

这里的“经验”有两个方向。

第一个方向是 **对别人有用**：

```plaintext
Personal Experience
个人经历

↓ 提炼、脱敏、授权、表达

Shared Experience Knowledge
共享经验知识
```


比如：

- 展会逛展攻略
- 某款 AI 眼镜真实体验
- 某个供应商合作踩坑
- 一条旅行路线
- 一个产品研究方法
  
它不一定公开，也不一定来自小红书或社区。它可能来自：

- 我主动分享
- 我的 Agent 帮我整理后分享
- 他人的 Agent 授权分享给我
- 团队内部沉淀的经验
  
所以 Shared Experience 的本质是：

> 来自某个主体的真实经历，经过提炼和授权后，可以被他人使用的经验资产。

第二个方向是 **对未来行动有用**：

```plaintext
Repeated Practice / Effective Procedure
重复实践或有效做法

↓ 模式识别、流程化、用户确认

Skill
可执行技能
```


比如：

你多次让 Agent 做智能眼镜竞品研究，形成稳定流程：

```plaintext
收集产品
→ 对比参数
→ 提取你关心的维度
→ 总结趋势
→ 给出决策建议
```


这就不只是记忆，而可以变成 Skill。

这条线的核心价值是：

> 让经验不只被保存，还能被传播或执行。

它产出的主要资产是：

- Shared Experience Knowledge
- Skills
- Procedures
- Playbooks

Skill 还可以形成闭环：

```plaintext
Memory → Pattern → Procedure → Skill → Better Action → New Memory
```


这让系统从“知道我”进一步变成“帮我越来越会做事”。

技能的传播：
```plaintext
只给自己
给朋友
给团队
给兴趣社区
公开发布
允许 Agent 网络使用
```


比如：

- 我的展会逛展经验
- 某款 AI 眼镜真实佩戴体验
- 某个供应商合作踩坑
- 某条旅行路线
- 某个任务流程的复盘
  
这些都可能来自人，也可能来自人的 Agent。

# Context Object 

三条主线最后不是混成一团，而是进入一个统一上下文层。

## Context Object Model

Context Object 是系统中可被管理、召回、更新、分享或执行的最小上下文单元。

它可以是一段记忆、一个任务、一个洞察、一个知识引用、一条共享经验、一个 Skill、一个人、一个地点或一个主题。

每个 Context Object 都不只是内容本身，还要带有来源、证据、权限、置信度、时效性、状态和用途。

Context Object 通用结构：
```plaintext
Context Object
  ├─ content：内容
  ├─ type：Memory / Insight / Knowledge / Task / Shared Experience / Skill
  ├─ source：眼镜 / PC / 手机 / Agent / 公共知识 / 他人 Agent
  ├─ evidence：支撑它的原始记录或摘要
  ├─ permission：私人 / 小圈子 / 团队 / 公开
  ├─ confidence：确定 / 推测 / 未验证
  ├─ freshness：稳定 / 会过期 / 需要刷新
  ├─ status：未确认 / 已确认 / 已修正 / 已拒绝
  └─ actionability：只读 / 可编辑 / 可分享 / 可执行
```

## Context Object Types

主要 Context Object 类型：
```plaintext
1. Memory
我经历了什么。
我的经历、偏好、关系、承诺、任务、生活上下文。

2. Insight
这些经历说明了什么。
AI 从我的记忆和行为中反思出的高阶理解，比如我真正关心什么、我反复形成什么判断。

3. Interest Knowledge：
经过我的兴趣、项目、任务过滤后的个性化知识状态。

4. Knowledge Reference：
外部知识的来源、摘要、引用、时间戳和可信度。


5. Task Context
我现在正在做什么。
我正在做什么、目标是什么、进展到哪、卡在哪里、谁参与、下一步是什么。

6. Shared Experience
哪些经验可以给别人用，或被别人给我用。
来自我或他人的经历，经过脱敏、整理、授权后，可以给别人使用的经验资产。

7. Skill
哪些经验可以被重复执行。
从重复经验、明确指令、公共最佳实践或他人共享经验中沉淀出的可复用流程。

8. Relationship / Persona Context
我和人、Agent、组织之间的长期关系与互动习惯。
```

# Context Orchestration

> 根据当前任务决定召回、刷新、组合、提醒、执行什么。

Agent 在执行任务时，不是只召回“记忆”，而是按任务需要组合这些资产。

比如你问：“帮我写一篇关于 AI 眼镜个人上下文系统的文章。”它可能调用：

```plaintext
Memory：
我们之前讨论过的框架演进。

Insight：
你真正关心的是经历、知识、经验如何转化为上下文资产。

Knowledge：
近期 AI 眼镜和 Agent memory 的外部资料。

Shared Experience：
你或他人关于智能眼镜使用体验的经验。

Skill：
你偏好的文章生成流程和结构。
```


**上下文编排层**位于“统一上下文资产层”和“Agent 使用层”之间。它的作用不是继续存储信息，而是在具体任务发生时，判断应该调用哪些上下文资产、如何组合、是否需要刷新、是否允许使用，以及以什么方式提供给 Agent。

它回答的是：

> 在当前场景下，哪些上下文应该被带入，哪些不应该被带入？


| 编排对象 | 作用 | 例子 |
| --- | --- | --- |
| Memory | 判断哪些私人记忆与当前任务相关 | 用户正在写 AI 眼镜文章时，召回此前关于长期记忆、隐私、共享经验的讨论 |
| Task Context | 判断当前任务目标、进展、约束和下一步 | 用户正在整理框架，系统知道现在重点是收束概念，而不是继续扩展 |
| Personal Insight | 判断哪些高阶洞察能帮助当前思考 | 召回“用户关注的不是记录更多，而是上下文资产如何可控、可复用、可分享” |
| Interest Knowledge | 判断哪些兴趣知识需要进入当前任务 | 用户讨论智能眼镜时，带入近期相关产品、论文、行业趋势 |
| Knowledge Reference | 判断是否需要引用、校验或刷新外部知识 | 如果涉及最新产品参数，先检查来源和时间戳 |
| Shared Experience | 判断是否有他人经验可作为参考 | 调用某个用户或小圈子分享的真实试戴体验 |
| Skills | 判断是否有可执行流程可以直接调用 | 写竞品分析时调用“产品研究流程”：收集、对比、总结、建议 |
| Relationship & Persona Context | 判断如何适配用户和 Agent 的长期互动方式 | 用户偏好结构化、阶段性总结，因此回答时优先给框架和收束 |


上下文编排层主要做几类决策：


| 决策类型 | 说明 | 例子 |
| --- | --- | --- |
| 相关性判断 | 当前任务需要哪些上下文资产 | 写文章需要 Memory、Insight、Knowledge；设置提醒主要需要 Task Context |
| 优先级排序 | 多条上下文冲突或过多时，决定哪些优先进入 | 最近确认过的洞察优先于较早、未确认的推断 |
| 刷新判断 | 判断外部知识是否需要更新 | 讨论“最新 AI 眼镜产品”时，需要刷新公共知识来源 |
| 权限判断 | 判断某条上下文是否允许被使用 | 私人记忆不能自动用于公开内容生成，除非用户授权 |
| 置信度判断 | 判断某条信息是否足够可靠 | 未确认的 Personal Insight 只能作为假设表达 |
| 场景适配 | 根据当前场景决定主动还是被动调用 | 会议中轻提示，复盘时完整展开 |
| 冲突处理 | 当记忆、知识或用户新反馈冲突时，决定如何处理 | 用户修正旧记忆后，旧版本降权或归档 |
| 组合生成 | 把不同资产组织成 Agent 可用的上下文包 | 为写作任务组合：过往讨论 + 核心洞察 + 外部资料 + 写作 Skill |


可以把它理解成一个 **Context Router / Context Orchestrator**：

```plaintext
当前任务 / 当前场景
        ↓
识别意图、目标、约束
        ↓
选择相关上下文资产
        ↓
检查权限、置信度、时效性
        ↓
必要时刷新或请求用户确认
        ↓
组合成 Agent 可用的上下文包
```


这层的核心价值是：

> 让 Agent 不是“想起所有东西”，而是在正确时间想起正确的东西，并以正确边界使用它。

# Agent 使用层

> 对话、任务执行、主动提醒、复盘、内容创作、经验分享、技能调用。

Agent 使用层是上下文系统最终产生价值的地方。统一上下文资产经过编排后，会进入 Agent 的对话、任务、提醒、复盘、创作和执行过程。

它回答的是：

> Agent 拿到这些上下文之后，具体如何帮助用户？


| 使用场景 | 调用的上下文资产 | 作用 | 例子 |
| --- | --- | --- | --- |
| 对话个性化 | Memory、Personal Insight、Persona Context | 让 Agent 更理解用户背景、偏好和表达方式 | 用户继续讨论框架时，Agent 知道不需要从零解释“共享经验知识” |
| 任务执行 | Task Context、Skill、Knowledge Reference | 帮用户更高效完成具体任务 | 自动按用户惯用流程生成竞品研究表和决策建议 |
| 主动提醒 | Task Context、Memory、Relationship Context | 在合适时机提示承诺、风险或相关信息 | 见到某人时提醒上次聊过的项目进展 |
| 个人复盘 | Memory、Task Context、Personal Insight | 帮用户总结阶段性经历、判断和变化 | 总结这一周围绕 AI 眼镜上下文系统形成了哪些关键观点 |
| 知识更新 | Interest Knowledge、Knowledge Reference、Watchlist | 把世界变化和用户兴趣连接起来 | 新 AI 眼镜发布后，判断是否影响用户已有产品判断 |
| 内容创作 | Memory、Insight、Shared Experience、Knowledge Reference、Skill | 把个人经历、外部知识和表达流程组合成内容 | 生成小红书攻略、产品复盘、行业文章或演讲稿 |
| 经验分享 | Shared Experience、Memory、Governance Metadata | 将私人经历脱敏、整理、授权后分享给别人 | 把展会试戴经历整理成可公开发布的攻略 |
| 技能调用 | Skill、Task Context、User Preference | 用已有流程完成重复任务 | 用户说“做个产品对比”，系统自动调用固定研究 Skill |
| 技能改进 | Skill、New Memory、User Feedback | 根据新执行结果优化已有流程 | 用户指出对比维度不够，Skill 更新为以后加入“佩戴舒适度” |
| 决策辅助 | Interest Knowledge、Memory、Personal Insight、Task Context | 把外部变化和个人判断结合 | 帮用户判断某款眼镜是否值得继续研究或购买 |
| 社交辅助 | Relationship Memory、Shared Context、Permission Metadata | 在人际互动中提供上下文，但控制边界 | 提醒某位朋友上次推荐过某款产品，但不暴露敏感私人内容 |
| 行动建议 | Personal Insight、Task Context、Skill | 从理解走向下一步行动 | 建议下一步先收束概念分类，再画系统架构图 |


Agent 使用层可以分成三种使用方式：


| 使用方式 | 含义 | 例子 |
| --- | --- | --- |
| 被动响应 | 用户问了，Agent 再调用上下文回答 | “我们上次讨论到哪了？” |
| 主动辅助 | 系统判断当前场景值得提醒或补充 | “你现在写这部分时，可能需要把 Skill 和 Shared Experience 分开。” |
| 自动执行 | 在权限允许下，Agent 直接调用 Skill 完成任务 | 自动整理会议纪要、生成竞品表、更新研究摘要 |


这一层最重要的设计原则是：


| 原则 | 含义 |
| --- | --- |
| 上下文够用即可 | 不需要每次调用所有记忆，只调用当前任务必要的部分 |
| 私人信息谨慎使用 | 私人记忆进入公开内容前必须脱敏或确认 |
| 推断要标明不确定性 | Personal Insight 如果未确认，应以“我猜测”或“可能”表达 |
| 主动提醒要克制 | 尤其在眼镜场景中，提醒要短、准、少打扰 |
| 技能执行要有边界 | 可执行 Skill 涉及外发、修改、购买、联系他人时需要确认 |
| 使用后反哺系统 | Agent 的执行结果、用户反馈和新信息会回流，更新 Memory、Insight 或 Skill |


可以用一个闭环表示：

```plaintext
上下文资产
   ↓
上下文编排
   ↓
Agent 使用
   ↓
用户反馈 / 新行为 / 新结果
   ↓
更新 Memory、Insight、Knowledge、Shared Experience 或 Skill
```


所以这两层放在整个系统里，可以这样总结：

> 上下文编排层决定“该想起什么、能不能用、怎么组合”；Agent 使用层决定“这些上下文如何在对话、任务、提醒、创作、分享和执行中产生价值”。

# 横向机制

横向机制不是第四条主线，而是贯穿整个系统的影响与约束。

> *除了纵向的信息转化链路，系统还存在两类横向机制：一类负责约束，另一类负责取向。它们贯穿输入、理解、资产沉淀、上下文编排和 Agent 使用全过程。*

## Agent Persona & Relationship

> *Agent Persona 是横跨理解、反思、召回和表达的处理透镜；Relationship & Persona Context 是系统长期沉淀的上下文资产。前者影响 Agent 如何工作，后者记录 Agent 如何适配这个用户。*

Agent Persona & Relationship 是系统中的横向机制之一。它不是第四条转化主线，也不是单纯的记忆类型，而是贯穿理解、提取、反思、召回、表达和行动的影响层。

它回答的是：

> 同样一批上下文，Agent 会用什么视角理解？用什么方式总结？在什么时候主动想起？以什么语气和关系姿态表达？

这里需要区分两个概念：

```plaintext
Agent Persona
Agent 的基础性格、角色定位和工作取向。
它影响 Agent 如何看待信息、如何组织回答、如何主动行动。

Relationship & Persona Context
Agent 和特定用户长期互动后沉淀下来的关系上下文。
它记录用户偏好、互动习惯、共同概念、信任边界和协作方式。
```


简单说：

```plaintext
Agent Persona：Agent 原本是什么样的。
Relationship & Persona Context：Agent 和我相处久了以后，学会了如何适配我。
```


它主要影响五类动作：

```plaintext
Extract
影响 Agent 从原始信息中优先提取什么。

Reflect
影响 Agent 如何从记忆中总结模式、偏好、信念和洞察。

Retrieve
影响 Agent 在当前任务中优先召回哪些上下文。

Share
影响 Agent 如何把经验整理成适合分享的表达。

Compile
影响 Agent 判断什么经验值得沉淀成 Skill。
```


不同 Persona 会导致不同的注意力权重。

比如，同一段信息是：

> 用户最近在反复讨论 AI 眼镜、长期记忆、隐私边界、共享经验和 Skill。

效率助理型 Agent 可能提取：

```plaintext
用户正在整理 AI 眼镜个人上下文系统框架。
当前任务是收束分类、完善文档结构。
下一步可能是输出架构图或 pitch deck。
```


研究伙伴型 Agent 可能提取：

```plaintext
用户正在区分 memory、knowledge、shared experience、skill 之间的边界。
核心问题是个人上下文系统如何把经历、知识和经验转化为资产。
```


陪伴型 Agent 可能提取：

```plaintext
用户在复杂框架中感到混乱，需要阶段性收束、澄清和共同梳理。
```


这些都不是“错”，但它们关注的切面不同。所以 Persona 的作用不是篡改事实，而是改变注意力分配和解释角度。

### Relationship & Persona Context 是长期资产

Relationship & Persona Context 是上下文对象层中的一种资产。它记录的是 Agent 和用户之间长期形成的互动模式。

它可能包括：

```plaintext
用户偏好：
用户喜欢结构化、阶段性总结，不喜欢空泛表达。

协作习惯：
用户常常先发散讨论，再要求收束成框架。

共同概念：
用户和 Agent 一起形成过 Personal Context System、Shared Experience Knowledge、Context Object 等概念。

信任边界：
用户允许 Agent 在研究讨论中主动提出框架，但涉及隐私分享和 Skill 执行时需要确认。

表达偏好：
用户更接受直接、清晰、有判断的表达，而不是过度铺垫。

角色关系：
这个 Agent 在用户这里更像研究伙伴，而不是单纯执行助理。
```


所以 Relationship & Persona Context 不是 Agent 的“自我人格”，而是：

> Agent 为了更好地服务这个用户而沉淀下来的关系记忆和协作模型。

它可以被用户查看、修正、删除，也应该能被迁移或重置。

### 它如何影响整个系统

Agent Persona & Relationship 会横向影响系统的多个环节。

```plaintext
在理解阶段：
影响 Agent 如何理解一段经历的重点。

在提取阶段：
影响哪些信息会被认为值得写入上下文对象。

在反思阶段：
影响 Personal Insight 的生成角度。

在召回阶段：
影响当前任务优先调用哪些上下文。

在编排阶段：
影响上下文组合方式、主动提醒时机和表达深度。

在分享阶段：
影响 Shared Experience 如何被整理成别人能理解的内容。

在技能阶段：
影响哪些重复行为会被识别为可沉淀的 Skill。

在表达阶段：
影响回答的语气、结构、主动性和边界感。
```


比如：

```plaintext
同样是用户说“我有点乱”。

任务型 Agent：
可能直接整理待办和下一步。

研究伙伴型 Agent：
可能先重构问题框架，再指出概念边界。

陪伴型 Agent：
可能先回应用户的困惑，再慢慢收束。
```


这说明 Persona 会影响 Agent 如何帮忙，但不能替代事实判断。

### 必须区分事实、解释和性格

为了避免 Persona 污染记忆系统，需要把系统分成三层。

```plaintext
Fact Layer
事实层：发生了什么。
比如：用户讨论了 AI 眼镜、PC、手机、共享经验、Skill、Agent Persona。

Interpretation Layer
解释层：Agent 如何理解这些事实。
比如：用户正在构建一个跨设备个人上下文系统。

Persona Layer
性格层：Agent 用什么视角总结、提醒、陪伴和表达。
比如：研究伙伴型 Agent 会把它整理成理论框架；执行助理型 Agent 会把它整理成任务清单。
```


这三层要有不同规则：

```plaintext
事实层：
尽量客观，必须可追溯到证据。

解释层：
允许推断，但要标注置信度，重要洞察最好让用户确认。

性格层：
可以影响表达和注意力，但不能改写事实，不能绕过权限。
```


尤其是 Personal Insight 这类高阶结论，不能被 Agent 以过度确定的方式写入长期系统。更好的状态是：

```plaintext
Hypothesis
Agent 猜测出的洞察。

Confirmed
用户确认后的洞察。

Corrected
用户修正后的洞察。

Rejected
用户否认后的洞察。
```


### Agent 可以适配用户，但不能失控漂移

长期互动中，Agent 的表现一定会变化。它会越来越懂用户的表达方式、关注点、项目背景和协作习惯。

这是必要的个性化：

```plaintext
它知道用户喜欢先搭框架再展开。
它知道用户正在研究 AI 眼镜个人上下文系统。
它知道用户对隐私、共享经验和 Skill 的边界很敏感。
它知道用户希望它在混乱时帮助收束，而不是继续发散。
```


但这种变化应该被理解为：

> Agent 对用户的适配，而不是 Agent 基础人格无边界地改变。

系统应该允许：

```plaintext
适配用户偏好
记住共同概念
形成协作默契
调整表达方式
优化主动提醒方式
```


但不应该允许：

```plaintext
因为用户情绪激烈，Agent 也变得偏激。
因为关系变熟，Agent 越过隐私边界。
因为用户喜欢某个结论，Agent 忽略事实校验。
因为长期互动，Agent 把未经确认的判断当成事实。
因为某种 Persona 倾向，Agent 系统性忽略其他重要信息。
```


所以 Agent Persona & Relationship 需要被 Governance / Evidence / User Control 约束。

## Governance / Evidence / User Control

> 隐私、权限、来源、证据、置信度、时效、确认、删除、分享、可解释。

### Governance

每条资产都需要记录：

```plaintext
来源：眼镜 / PC / 手机 / 对话 / 公共知识 / 他人 Agent
主体：关于我 / 关于别人 / 关于世界 / 关于组织
类型：记忆 / 任务 / 洞察 / 知识 / 共享经验 / 技能
敏感度：低 / 中 / 高
权限：私人 / 小圈子 / 团队 / 社区 / 公开
置信度：确定 / 推测 / 未验证
时效性：稳定 / 会过期 / 需要刷新
状态：未确认 / 已确认 / 已修正 / 已拒绝
用途：个性化 / 任务辅助 / 推荐 / 分享 / 技能执行
可操作性：只读 / 可编辑 / 可删除 / 可分享 / 可执行
```


不同主线的治理重点不同：

```plaintext
经历线：
重点是隐私、确认、删除、误解修正。

知识线：
重点是来源、时效、更新、冲突处理。

经验线：
重点是脱敏、授权、适用条件、可执行边界。
```


当用户新反馈、旧记忆、外部知识或 Agent 推断发生冲突时，系统应优先采用用户最新确认的信息；旧版本不直接删除，而是降权、归档或保留为历史版本。

### Evidence

> *所有高阶结论，尤其是 Personal Insight、Interest Knowledge、Shared Experience 和 Skill，都必须能追溯到证据；否则它们只是 Agent 的主观生成。*


```plaintext
Evidence 负责回答：
这条记忆从哪里来？
这个洞察基于哪些经历？
这个知识结论引用了哪些来源？
这个共享经验是否经过授权？
这个 Skill 是从哪些重复行为或明确指令中沉淀出来的？

```


### User Control
```plaintext
User Control 负责让用户能够：
查看系统记住了什么
修改错误记忆
确认或否认 Personal Insight
允许或撤回共享经验
管理数据源权限
安装、编辑、禁用 Skill
查看某个回答为什么引用了某条上下文
```

## 上下文系统和 AI 主动性的关系

你这个问题问到点子上了。

### 没有上下文系统，AI 主动性是危险的
```plaintext
用户戴着 AI 眼镜在街上走
  → Agent 看到一个熟人
  → 没有 Relationship Context：
      Agent 不敢提醒（怕说错话）
      或者乱提醒（说了不该说的）
  
  → 有 Relationship Context：
      Agent 知道：
        这是谁
        上次聊了什么
        什么能提什么不能提
        当前场景是否适合提醒
      → 精准、克制、有用的提醒复制
```

### 上下文系统是主动性的「刹车」和「方向盘」
```plaintext
主动性没有上下文 = 乱跑
    → 不该提醒的时候提醒
    → 不该说的话说了
    → 用户被打扰、被冒犯

主动性 + 上下文 = 恰到好处
    → 该说的时候说
    → 说该说的话
    → 用户觉得「这个 Agent 懂我」复制
```

### 你的框架里，主动性由 Orchestration 层控制
```plaintext
Agent 想主动做一件事
    ↓
Orchestration 层判断：
    1. 相关性：这个提醒和当前场景有关吗？
    2. 权限：这条信息允许在这个场合用吗？
    3. 场景适配：现在适合打扰用户吗？
    4. 置信度：我确定这个信息是对的吗？
    ↓
全部通过 → 主动提醒
任一不通过 → 憋着复制
```

所以上下文系统不是让 AI 更被动，而是让 AI 的主动性变得可信。

没有上下文的主动性是骚扰。有上下文的主动性才是智能。
