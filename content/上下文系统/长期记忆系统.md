# 🧠 长期记忆系统 (Multi-Source Long-Term Memory System)

> *让 Hermes 拥有「操作记忆」—— 不仅记住对话，还能记住你在电脑上做了什么。*

---

## 🎯 项目目标

构建一个**多输入源的长期记忆系统**，将 macOS 用户操作行为数据（屏幕内容、应用事件）注入 Hindsight，使 Hermes 能同时理解用户的**对话上下文**和**操作行为**，形成更完整的个人记忆。

### 核心能力

| 能力 | 说明 |
|------|------|
| 🔍 **被动查询** | 「我昨天下午在写什么？」—— Hermes 能回答 |
| 👁️ **主动感知** | Hermes 知道当前在哪个应用、编辑什么文件 |
| 📈 **长期习惯** | 「我每周三下午通常在做什么？」—— 模式识别 |
| 🔗 **交叉关联** | 聊天提到的话题 + 实际操作的上下文 |

---

## 🏗️ 系统架构

```
┌─────────────────────────────────────────────────────┐
│                 工作 Mac (日常使用)                    │
│                                                       │
│  Screenpipe ──┐                                      │
│  (屏幕录制)    ├──→ 读取脚本 ──→ HTTP POST ──────┐    │
│  OpenChronicle ┘    (每5min)       │              │    │
│                                    │              │    │
└────────────────────────────────────┼──────────────┘    │
                                     │                    │
                                     ▼                    ▼
                              ┌──────────────────────────────┐
                              │     本机 Mac (Hermes 运行)     │
                              │                               │
                              │  Hindsight API (localhost:8888)│
                              │  ┌─ /memories (POST)          │
                              │  │  content: 自然语言描述      │
                              │  │  metadata: 原始结构化数据   │
                              │  └──────────────────────────  │
                              │                               │
                              │  Hermes Agent                  │
                              │  └─ hindsight_recall()         │
                              │     hindsight_reflect()        │
                              └──────────────────────────────┘
```

### 数据流

**原始采集 → 结构化缓存 → 语义化转换 → 记忆注入 → 智能查询**

---

## 📦 数据源

### Screenpipe (屏幕+音频录制)

- **用途**: 捕获屏幕上看到的文字、代码、网页、视频
- **存储**: 本地 SQLite
- **粒度**: 连续帧级，可 OCR 提取文字
- **优劣**: 信息最完整，但隐私风险大、数据量大
- **Repo**: [mediar-ai/screenpipe](https://github.com/mediar-ai/screenpipe)

### OpenChronicle (AX 事件记录)

- **用途**: 记录应用切换、文件编辑、URL 访问、剪贴板操作
- **存储**: Markdown + SQLite 索引
- **粒度**: 事件级，包含应用名、窗口标题、时间戳
- **优劣**: 结构化好、隐私风险低，但缺少屏幕内容
- **Repo**: [Einsia/OpenChronicle](https://github.com/Einsia/OpenChronicle)

## 🔄 数据转换设计

Hindsight 要求记忆输入有两层结构：

| 字段 | 内容 | 示例 |
|------|------|------|
| **content** | 自然语言描述（供 LLM 提取事实） | "用户在 VS Code 中编辑了 Hermes 配置文件的 provider 部分" |
| **metadata** | 原始结构化数据（无损保存） | `{"app":"VS Code","file":"config.yaml","action":"edit","timestamp":"..."}` |

**为什么不直接用 JSON 推？** Hindsight 的 `content` 字段是 `StrictStr`，被直接喂给 LLM 做实体提取。自然语言能让 Hindsight 正确理解语义，而 `metadata` 保留所有原始数据用于精确查询。

---

## 🚀 实施方案（方案四：直接 API 推送）

**选型理由**: 本机 Mac 永远在线（运行 Hermes + Hindsight），工作 Mac 开机时可访问本机。架构最简洁，数据零损失。

### 步骤

- [ ] **Step 1**: 工作 Mac 上确认 Screenpipe 和 OpenChronicle 的数据位置与结构
- [ ] **Step 2**: 编写数据读取 & 推送脚本（增量读取，维护 last_push_timestamp）
- [ ] **Step 3**: 部署为 launchd 后台服务（每 5 分钟运行一次）
- [ ] **Step 4**: 验证 Hermes 能通过 hindsight_recall/reflect 查询操作记忆
- [ ] **Step 5**: 优化：去重（document_id）、错误重试、推送日志

### 关键技术参数

- **API**: `http://192.168.193.40:8888`（本机 Hindsight）
- **bank_id**: `hermes`
- **去重策略**: 各数据源的 `document_id`（Screenpipe 用 frame_id，OpenChronicle 用 event_id）
- **增量标记**: `last_push_timestamp` 文件，记录上次推送时间

## 🗺️ 项目路线图

```
Phase 1 ─── 基础搭建
  ├── 确认数据结构 & 网络连通
  ├── 单数据源手动推送验证
  └── launchd 自动部署

Phase 2 ─── 双数据源
  ├── Screenpipe + OpenChronicle 并行推送
  ├── 去重 & 增量逻辑完善
  └── 数据一致性验证

Phase 3 ─── 智能增强
  ├── 本地 LLM 摘要（在工作 Mac 推前摘要高频事件）
  ├── 隐私过滤（过滤敏感应用/关键词）
  └── 实时推送（watchdog 监听文件变更）

Phase 4 ─── 场景落地
  ├── Hermes 对话中自动引用操作记忆
  ├── 工作习惯分析与回顾
  └── 多设备记忆融合（Mac + Win VM + ...）
```
