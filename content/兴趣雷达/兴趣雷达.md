# 兴趣雷达

## 一句话定义

兴趣雷达是一个**相关性判断引擎**：你给它一段外部内容，它用你的个人上下文系统来判断这条内容和你有多相关、为什么、该不该看。

> 核心问题：给我一段外部内容，判断它和我有什么关系？

## 产品形态

兴趣雷达是一个 **SKILL.md 定义的工作流**，不是插件，不是 Python 库，不绑定任何 Agent 平台。

它通过 SKILL.md 指导 Agent 的行为。任何能执行该流程的 Agent（Hermes、Claude Code、Codex、Cursor、OpenClaw、ChatGPT 等）都可以使用。

**平台无关**：SKILL.md 中不出现任何特定平台的工具名（如 hindsight_recall、browser_navigate），全部抽象为"Agent 可用的记忆/搜索工具"。Agent 在运行时自适应探测可用工具。

代码层面的实现（如 snapshot.py 快照管理脚本）交给 Claude Code 编写。

## 定位

兴趣雷达只做中间层，不碰两端。

```text
已有的内容推送来源
（用户转发 / 已有推送 Skill / 微信群 / RSSHub / Folo / GitHub watching / 即刻）
    ↓
    兴趣雷达（相关性判断引擎）
    ├── 自适应上下文召回
    ├── 实体抽取
    ├── 兴趣匹配
    ├── 项目关联
    ├── 综合评分 + why_it_matters
    └── 反馈闭环（越用越准）
    ↓
增强后结果
（分数 + 原因 + 关联上下文 + 建议 + 置信度）
```

**不采集内容，不负责推送，不存数据。只做一件事：判断。**

## 设计原则

### 平台无关

兴趣雷达不绑定任何特定 Agent 平台。它通过 SKILL.md 描述工作流，任何能执行该流程的 Agent 都可以使用。

**Agent 不预设任何工具。** 运行时自适应探测当前环境可用的工具，选择最优方案执行。

### 自适应上下文召回

Agent 按以下优先级顺序探测可用的上下文工具，**不预设使用哪个**：

| 优先级 | 上下文源 | 探测方式 |
|--------|---------|---------|
| 1 | 快照缓存文件 | 检查本地缓存文件是否存在、是否过期（TTL 6h） |
| 2 | 记忆系统召回 | 尝试调用 Agent 可用的记忆/搜索工具 |
| 3 | 项目笔记扫描 | 检查本地笔记目录是否存在（如 Obsidian Vault） |
| 4 | 最小种子兴趣 | 以上全部不可用时回退 |

### Skill 只定义接口，不绑定实现

SKILL.md 只定义 `judge()` 和 `batch_judge()` 两个接口的行为流程。配置驱动运行，不内置任何平台/工具假设。

### 非目标

- ❌ 不采集内容（不维护 sources.yaml，不做 RSS/GitHub scraping）
- ❌ 不推送内容（不负责交付，不维护 cronjob）
- ❌ 不存储事件历史
- ❌ 不做订阅管理

## MVP 三个能力

### MVP 1：转发/粘贴即用 ✅

用户在聊天中转发或粘贴一条内容，Agent 自动触发 judge。

触发条件：用户在消息中包含链接 + 询问/转发意图（"你看看"、"这个跟我有关吗"、"解读一下"等）。

核心流程：获取内容 → 实体抽取 → 上下文召回（自适应）→ 六维度评分 → 生成 why_it_matters → 输出

### MVP 2：batch_judge — 其他推送 Skill 的增强器 ✅

其他推送 Skill（如 xr-weekly、aigc-weekly、follow-builders 等）在推送前调用 batch_judge 过滤，只推送 top 档位内容。

| 场景 | items 数量 | 执行策略 |
|------|-----------|---------|
| 小批量 | ≤ 3 条 | 完整 judge |
| 中批量 | 4-10 条 | 共享上下文召回 + 逐条评分 |
| 大批量 | > 10 条 | 先 title 初筛 → top_k × 3 条完整判断 |

### MVP 3：反馈闭环 ✅

用户对判断结果的反馈（confirm/dismiss）自动影响后续判断。

**自适应存储：** 不绑定特定记忆工具。按优先级使用 hindsight_retain → memory → 快照文件。

**影响机制：**
- confirm：同类内容评分更自信
- dismiss：同类内容降分 10-20 分
- 多次 dismiss（≥ 3 次）：同类内容降入 ignore
- 多次 confirm（≥ 3 次）：同类内容上调 5-10 分

## 接口

### judge（单条）

输入：title, summary, url?, source?
输出：relevance_score, bucket, why_it_matters, confidence, action

### batch_judge（批量）

输入：items[{title, url, content, source, event_type}], top_k
输出：results[{index, score, bucket, why_it_matters, confidence, action}], summary

## 判断流程

```text
输入内容
  ↓
① 内容获取（web_extract → browser fallback）
  ↓
② 实体抽取（技术词、产品名、组织、事件类型）
  ↓
③ 上下文召回（自适应：快照 → Hindsight → Obsidian → Memory → 种子兴趣）
  ↓
④ 六维度评分（项目影响 35%、兴趣匹配 20%、变化幅度 15%、可行动性 15%、来源可信度 10%、时效性 5%）
  ↓
⑤ 生成 why_it_matters（必须关联具体项目/兴趣/决策）
  ↓
⑥ 输出结果
```

## 反馈闭环流程

```text
兴趣雷达输出判断结果
  ↓
用户回复反馈（confirm / dismiss）
  ↓
Agent 识别反馈类型
  ↓
自适应存储（hindsight_retain → memory → 快照文件）
  ↓
下次 judge 时，上下文召回自动带回反馈记录
  ↓
Agent 在评分时自然调整
```

## 最小种子兴趣（回退方案）

当没有任何上下文系统可用时：
- XR / spatial computing
- AI agents（Claude Code、Codex、MCP、agent）
- Personal context / memory systems
- HomeLab / local inference（Ollama、llama.cpp、Docker、PVE）

> 这只是回退。一旦用户配置了上下文系统，兴趣模型完全从上下文动态推导。
